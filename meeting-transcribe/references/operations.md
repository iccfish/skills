# 任务状态、恢复与工具链

## 任务记录

`.task.json` 保存原媒体路径、整组产物路径、百炼 API 地址、OSS Endpoint/Bucket、UUID 对象 key、模型、分离设置、task_id、phase 和 cleanup。它不保存密钥/签名 URL，但包含本地路径及站点信息，属于本机数据，不应提交仓库。

```bash
python scripts/transcribe.py --resume "会议.task.json" --no-voiceprint
```

恢复要求使用同一百炼地址与 OSS Endpoint/Bucket，并提供原账号凭据；脚本只能核对这些配置，不能仅凭地址判断是否同一云账号。保持整组文件位置不变。已保存 JSON 时直接重生成并重试清理，不重新下载或提交。

| phase | 行为 |
|---|---|
| PREPARED / UPLOADING / UPLOAD_FAILED | 尚未提交；恢复仅尝试清理已知对象，然后可重新处理原媒体 |
| SUBMITTING / SUBMIT_UNKNOWN 且无 task_id | 可能已提交；保留对象，禁止自动重提，需先核对云端任务 |
| SUBMITTED / FETCHING | 有 task_id；恢复查询并下载，不再提交 |
| SAVING | 可能已保存但检查点未更新；存在有效 JSON 时直接使用，否则继续查询下载 |
| SAVED | 原始结果已保存；重试 pending 清理并重生成派生文件 |
| FAILED | 明确终态失败；可重试清理，不重新提交 |

`cleanup` 为 pending/deleted/kept/not_uploaded。`--keep-oss` 的决定保存在任务记录，恢复时沿用；手动保留的对象需自行删除。清理仅针对任务记录中的对象，不遍历或清空 Bucket。

轮询超时、断网、UNKNOWN 都不等于云端任务失败。明确失败终态和明确拒绝的提交可清理；状态未知保留音频。若提交响应丢失且没有 task_id，不能保证自动找回任务，应先人工核实，再决定是否重新提交及删除遗留对象。没有取消/删除云任务命令。

转写结果链接有保留期限，应及时恢复取回；任务记录无法延长云端保留期。签名音频 URL 过期也不会自动更新已提交任务的输入。需要兜底的 OSS 生命周期应由用户在 Bucket 上另行配置，脚本不修改它。

恢复云任务成功后，保存原始稿并完成首次暂定归属后停在校准审核；已有归属快照则直接复用。`--from-json ... --continue` 是用户明确继续后才使用的本地阶段，不等同于云任务恢复。`-原始转写稿.txt` 只创建一次；归属未确认版及其 `.attribution.json` 快照只创建一次；归属校准版与说话人分离各有独立文件，后续修改不覆盖未确认版。meta 的 workflow 保存审核版本和阶段，`.samples.json` 保存采样决定，均为本机私人产物。

## 音频与工具

视频抽取音轨；非 MP3 或超出单声道、128kbps、44100Hz 条件的输入转为 16kHz/64kbps/单声道 MP3。符合条件的 MP3 直接复用。转码产物保留在本地便于重听和声纹处理。

始终分别检查 ffmpeg 与 ffprobe，不将 ffmpeg 当作 ffprobe。工具发现顺序为显式 FFMPEG_DIR、用户缓存、旧项目 `.tools/ffmpeg`、PATH。Windows x64 缺失时可下载同时包含两者的工具包；其他平台/架构需先安装完整工具链并放入 PATH 或指定目录。下载和模型缓存均不写安装目录。

`--dry-run` 只准备本地音频，可能下载缺失且已适配的工具链，不上传或调用模型。`--check-env` 仅检查，不下载。进程被强杀留下的锁和未完成转码文件需要先核对，再手动处理。

## 失败与结果

退出 0 完成、1 自检缺关键项、2 配置/输入/处理失败、3 声纹待决、4 批处理部分失败。清理 pending 或人工调整 skipped/warnings 会在日志与记录中提示；退出 0 不代表这些附加事项已全部解决。

原始 JSON 保存先于名单/声纹操作。首次归属匹配失败会提示并保留原库，未命中保留编号供人工命名；开关待决退出 3 后用本地 JSON 继续。已有快照后的校准和继续不再匹配，沿用首次归属加人工姓名。采样导出失败不丢弃已保存分离稿，可重新继续或显式重新采样；未确认不得入库。名单/声纹损坏、旧版不兼容或并发冲突时保留文件并报告。新任务的产物不覆盖既有文件，显式审核/继续会更新对应派生稿，原始稿始终不变。

采样决定处理完毕后进入最终 [HTML 会议纪要](report.md) 阶段；仍有 pending 则等待回答。报告失败不会重新转写或入库；修正正文或来源问题后单独运行 report.py。改稿后旧纪要可能过期，必须按最新确认结果重新整理，不能继续分发旧摘要。正文、HTML 和版本记录纳入新任务整组冲突检测。
