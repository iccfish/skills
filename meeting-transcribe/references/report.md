# 最终单页 HTML 会议纪要

## 何时生成

用户确认最终归属并明确继续，已生成分离稿且逐人采样选择已处理后，执行本阶段作为默认最终交付，无需用户再次请求纪要。accepted / rejected / insufficient 均可结束采样；pending 仍需等待用户回答，不能替用户选答案来生成最终报告。报告内容优先依据归属校准版对应的重放状态，没有校准版则用最终分离稿；不使用首次未确认稿代替最终内容。

`scripts/report.py` 独立运行，只依赖 Python 标准库，不调用额外模型 API、不上传、不写声纹库、不改稿件。正文由当前智能体阅读最终稿后整理，脚本校验来源版本、句索引与结构，再套用内置模板。脚本不声称自动理解语义或证明每条总结准确。

## 固定设计与内容结构

样式资源为 `assets/minutes.html` 与 `assets/minutes.css`。采用安静的纸面报告风格：浅灰底、白色正文、深蓝文字、青绿色强调，宋体标题配系统无衬线正文；小号章节编号和充足留白区分层级。不依赖 CDN、在线字体或图片。

一页包含：

1. 基本信息：会议标题、日期、形式/地点、主持/组织、转写覆盖至、按最终归属列出的发言人。发言人不等于完整出席名单。日期、地点及组织者不明则留空；文件名日期只作为有注明的推断，不能以报告生成日期替代会议日期。
2. 摘要：凝练会议重点；另列明确结论/安排与待澄清/风险，不能将争论、提案或发言人的外部判断写为既定事实。
3. 议程：按实际录音主题与顺序归纳，显示相对起止时间。会前闲聊可简要归为会前交流，不与正式议题混同。
4. 待办：事项/交付物、负责人、期限、状态及来源。未指定负责人用 null（显示待确认），未指定期限用 null（显示未明确）。保留“本周”“会后”等原文期限；日期锚点不可靠时不换算绝对日期。明确安排标待办；建议、未落实的后续标待确认，不根据发言人身份自动指派或声称已完成。
5. 生成物入口：实际存在的原始、未确认、校准、分离稿，ASR、调整/任务记录、原录音和处理音频。报告不展示声纹采样及确认信息，不提供采样清单或样本音频入口。缺失文件不创建空链接，不链接配置、Token、完整声纹向量库。相邻产物使用编码后的相对链接；跨盘用本机 file URI，外发前需另行打包，不上传报告或音频。
6. 来源核对：内嵌可折叠最终逐字稿，摘要、结论、议程要点、待办均有句索引可点击定位；拆句保留原索引并在同一来源块分别列姓名。报告可独立阅读，外部文件链接仍依赖原文件位置。

支持手机布局、待办状态筛选与打印/保存 PDF。打印恢复全部待办、展开来源逐字稿。报告本身不持久化“完成”勾选，也不修改待办系统。

## 智能体编写与生成

```bash
# 取得最终来源及版本；JSON 输出含全文，按需分段阅读
python scripts/report.py --from-json "会议.asr.json" --context
# 将整理好的内容保存到会议目录的 会议.minutes.json，再渲染
python scripts/report.py --from-json "会议.asr.json" --content "会议.minutes.json"
```

使用脚本绝对路径；工作目录保持会议目录。先完整阅读 context 的最终句内容（长会分段阅读），再整理，不能只凭开头、文件名或早先未确认摘要生成。每条总结、任务及建议要与引用的原话核对；对专有名词可据明确上下文归纳，但不要默默改写逐字稿。没有可支持的结论、问题或待办用空列表，页面会显示未明确。

内容 JSON schema 1：

```json
{
  "schema": 1,
  "source_sha256": "取自本次 context，不能从旧报告沿用",
  "review_revision": "取自本次 context",
  "title": "会议标题",
  "meeting_date": null,
  "location": null,
  "organizer": null,
  "source_note": "依据最终归属稿整理，发言中的外部事实未独立核验。",
  "summary": [{"text": "会议重点", "sources": [0]}],
  "decisions": [],
  "open_questions": [],
  "agenda": [{"title": "讨论主题", "start": 0, "end": 12, "points": [{"text": "讨论内容与结论", "sources": [0, 12]}]}],
  "tasks": [{"task": "待跟进事项", "owner": null, "due": null, "status": "待确认", "sources": [12]}]
}
```

sources 为原始零起始句索引；同一索引拆句时核对该句全部片段。议程 start/end 为覆盖该主题的原始句索引，每项 points.sources 必须在其范围内。summary、decisions、open_questions 中的条目均使用 text 与 sources；tasks 使用 task/owner/due/status/sources。

产物为 `会议-会议纪要.html` 及 `会议.report.json`；后者保存来源、校准版本、采样清单、内容与 HTML 摘要。正文 JSON、HTML 与 provenance 均是私人会议产物，已纳入忽略规则。新媒体任务把这些路径纳入整组冲突检查。

渲染前会重放当前调整、核对首次快照/最终稿/采样版本并拒绝未解决调整。转写变化后必须更新最终稿与采样状态，重新阅读新 context、更新正文，再生成；不通过仅替换旧正文中的摘要字段绕过重读。生成失败保留已有报告。报告生成不改变转写 workflow 的 separated 状态，也不重新执行声纹匹配或入库。

交付 HTML 可点击链接，并说明不明确的负责人/期限或关键争议；实际浏览宽屏和手机布局，检查来源跳转、待办筛选、打印样式与本地文件链接。静态版本检查不等于纪要语义准确率或转写准确率。
